「Claude Fable 5 が出たけど、Opus 4.8 から乗り換えるべき？」——2026年6月9日の公開以降、最も多い疑問がこれです。本記事は、Fable 5 と Opus 4.8 を**料金・速度・用途**で並べ、どちらをどう使い分けるかを実務目線で整理します。

> Fable 5 そのものの概要（Mythos との関係・安全機構・公開スケジュール）は[Claude Fable 5 とは（速報解説）](/guides/claude-fable-5-release/)にまとめています。本記事は「で、どっちを使う？」に絞った続編です。料金・仕様は Anthropic 公式発表（2026年6月9日）に基づきます。

## 結論：常用は Opus 4.8、難所だけ Fable 5

先に結論です（編集部見解）。

- **日常使い**（チャット・要約・メール・定型コーディング）→ **Opus 4.8**（コスパ重視なら Sonnet 4.6）
- **難所だけ**（大規模リファクタリング・長期自律タスク・難しい科学/数学・複雑な計画）→ **Fable 5**

理由はシンプルで、**Fable 5 は Opus 4.8 のちょうど2倍の料金**だからです。性能は確かに Fable 5 が上ですが、簡単な作業では差が体感しにくく、コストだけ倍になりがちです。

## 料金：きれいに2倍

| モデル | 入力（100万トークン） | 出力（100万トークン） | Opus 4.8 比 |
|---|---|---|---|
| **Claude Fable 5** | $10 | $50 | ×2.0 |
| **Claude Opus 4.8** | $5 | $25 | 基準 |
| Claude Sonnet 4.6 | $3 | $15 | ×0.6 |

### コスト試算（1やり取りあたり）

入力5万トークン・出力1万トークンの典型的なやり取りで比べると：

| モデル | 概算コスト |
|---|---|
| Sonnet 4.6 | 約 $0.30 |
| Opus 4.8 | 約 $0.50 |
| **Fable 5** | **約 $1.00** |

1回なら数十セントの差ですが、**1日100回回せば日 $50 の差**、月にすれば無視できない金額になります。「全部 Fable 5」が一番コストを溶かすパターンです。

## 性能差が「効く場面」と「効かない場面」

Fable 5 は一般提供モデルで最高水準とされますが、差が出るかは**タスクの難しさ次第**です。

### Fable 5 にする価値がある（難所）

- **大規模リファクタリング・コード移行**：公式事例でも約5,000万行規模の Ruby 移行を短期間でこなした例が挙げられています。やり直しコストが巨大な作業ほど、賢さの差が金額差を上回ります
- **長時間の自律エージェント**：何十手も先まで一貫して進める長期タスクで強み
- **難しい科学・数学・研究**：専門特化モデルを上回る結果も報告されています
- **複雑な意思決定・計画**：分岐や制約が多く、間違いの代償が高い場面

### Opus 4.8（や Sonnet 4.6）で十分（効きにくい）

- 日常のチャット・Q&A
- 文章の要約・翻訳・メール作成
- 定型的なコーディング、軽いバグ修正
- 分類・抽出などの単純作業 → **Sonnet 4.6** がコスパ最有力

> **編集部見解**：「賢いモデルほど良い」は半分正解で半分間違いです。簡単なタスクでは上位モデルの賢さが**出力に現れない**ため、料金だけが増えます。難易度とコストを見合わせるのが、AI を業務で使うときの基本姿勢です。

## 使う人別：現実的な選び方

### エンジニア

- **常用**：Opus 4.8（`high`〜`xhigh`）。Claude Code のデフォルトでも実用十分
- **難所だけ Fable 5**：大規模移行、入り組んだ設計判断、長時間の自律実装
- 詳しい開発ワークフローは[Claude Code 実践ガイド](/guides/claude-code-practical-guide/)へ

### ライター・マーケター

- **常用**：Sonnet 4.6 か Opus 4.8 で十分。文章生成は上位モデルでも体感差が小さい領域
- Fable 5 が効くのは、長い資料を横断した深い分析・構成など「考える比重が高い」作業に限られます

### 法人・チーム

- **基本**：Opus 4.8 を標準に据え、Fable 5 は「ここぞ」の案件用に予算を切る
- サブスクは6月22日まで無料枠があるので、**まず無料期間で ROI を検証**してから6月23日以降の課金を判断
- 中小企業での導入観点は[Claude を中小企業で使う](/guides/claude-for-small-business-2026/)も参照

## 意思決定フロー

```
そのタスクは「間違えると高くつく / やり直しが大変」？
├─ いいえ（日常・定型）
│   ├─ 速さ・コスト最優先 → Sonnet 4.6
│   └─ 品質も欲しい      → Opus 4.8
└─ はい（大規模・長期・高難度・高リスク）
    └─ Fable 5（難所だけ。終わったら常用モデルに戻す）
```

## API でコストを抑える4つの工夫

API で Fable 5 を取り入れるなら、無駄な出費を避ける設計が重要です。

1. **モデルのルーティング**：常用を Opus 4.8 / Sonnet 4.6 にし、難所だけ Fable 5 に振り分ける
2. **effort を上げすぎない**：用途に応じて `medium`〜`high`。何でも `max` にしない
3. **プロンプトキャッシュ**：繰り返す長い前提（システムプロンプト等）をキャッシュして入力コストを圧縮
4. **Task Budget**：長期エージェントには総トークンの上限を持たせ、暴走課金を防ぐ
